# Shukla Rugs Horizon storefront: homepage sections, collection, and product customization

The change customizes the stock Horizon theme in `shopify-live-horizon/` to match the Shukla Rugs Next.js storefront. It appends eight homepage sections to `templates/index.json` (Shop by Room, Shop by Category, Bhadohi Story, Brand Statement, Design Consultation, Reviews, Journal, Final CTA) composed entirely from existing Horizon sections, tunes the collection header and product-card typography in `templates/collection.json`, and adds metafield-guarded product detail rows to `templates/product.json` via a new `snippets/shukla-product-details.liquid` rendered through a merchant-editable `custom-liquid` block. All data-dependent sections ship empty (empty collection pickers, empty blog picker, empty media slots, a merchant-fill testimonial placeholder) so nothing is fabricated. Native commerce — media gallery, variant picker, buy buttons, product recommendations, collection filters/sorting/pagination — is left intact.

Watch for: the working tree has **uncommitted modifications to two `src/` files** (`src/app/layout.tsx`, `src/app/story/page.tsx`), which the task requires to stay completely unchanged (confirmed). Everything inside `shopify-live-horizon/` is correct and compliant; the scope violation lives outside the theme folder.

**Verdict**: NEEDS_CHANGES

### Product detail rows are fully guarded

`snippets/shukla-product-details.liquid` renders Story, Craft specifications (Material/Construction/Dimensions/Origin), Care, and Shipping & returns rows. Every value comes from `product.metafields.custom.*` and every row is wrapped in a `!= blank` guard, so a row is omitted when its metafield is absent or unconfigured. There are no hardcoded fallback values. The shipping/returns row links only to `shop.policies.shipping_policy` / `refund_policy` and is omitted when no policy exists — no fabricated shipping promises. The `metafield_tag` filter used here is the same one the baseline `blocks/disclosures.liquid` uses, so it is a valid Horizon filter. The namespace/keys (`custom.material`, etc.) are an assumption that must be reconciled with the live store's metafield definitions; until a key resolves, its row stays hidden, so an incorrect assumption fails safe (empty) rather than fabricating. (confirmed)
